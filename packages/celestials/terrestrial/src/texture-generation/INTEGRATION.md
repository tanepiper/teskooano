# Texture Generation Integration

The terrain texture generation system is integrated with both the **Solar System** and **Procedural Generation** packages automatically.

## How It Works

Since texture generation is **enabled by default**, all terrestrial planets and moons will automatically use the multi-pass texture generation system when rendered.

### Automatic Integration

1. **Solar System Package** (`@teskooano/systems-solar-system`):
   - Planets like Earth, Mars, Venus, Mercury, and the Moon already have `surface` properties defined
   - When these objects are rendered via `createMesh()`, texture generation happens automatically
   - The renderer starts texture generation asynchronously in the background
   - Uses procedural material initially, then upgrades to texture-based material when ready

2. **Procedural Generation Package** (`@teskooano/systems-procedural-generation`):
   - Planets generated by `PlanetGenerator` include `ProceduralSurfaceProperties`
   - When these procedurally generated planets are rendered, texture generation happens automatically
   - Same async generation pattern as solar system planets

### Data Flow

```
CelestialObject (with surface properties)
    ↓
createMesh() → BaseTerrestrialRenderer
    ↓
Constructor: Start async texture generation
    ↓
getLODLevels(): Create mesh with procedural material (fallback)
    ↓
update(): Check every 60 frames if textures are ready
    ↓
upgradeToTextureMaterialIfReady(): Switch to texture-based material
```

## Configuration

### Disable Texture Generation

To use the legacy procedural shader-based generation:

```typescript
createMesh(object, {
  ...options,
  useGeneratedTextures: false, // Use procedural shaders
});
```

### Custom Texture Generation Options

```typescript
createMesh(object, {
  ...options,
  textureGenerationOptions: {
    resolution: TEXTURE_RESOLUTIONS.HIGH, // 4096x2048
    skipErosion: false,
    skipCraters: false,
    normalStrength: 2.5,
    baseRoughness: 0.6,
  },
});
```

## Performance Considerations

- **Initial Load**: Texture generation happens asynchronously, so planets render immediately with procedural material
- **Upgrade**: Materials automatically upgrade to texture-based when generation completes (checked every 60 frames)
- **Memory**: Each planet uses ~32MB for all texture maps at 2048x1024 resolution
- **Generation Time**: Typically 1-5 seconds per planet depending on complexity and erosion settings

## Integration Points

### Solar System

No code changes needed. Solar system planets automatically use texture generation because:

- They have `surface` properties defined
- `useGeneratedTextures` defaults to `true`
- Renderer handles async generation automatically

### Procedural Generation

No code changes needed. Procedurally generated planets automatically use texture generation because:

- `PlanetGenerator` creates `ProceduralSurfaceProperties`
- `useGeneratedTextures` defaults to `true`
- Renderer handles async generation automatically

## Manual Texture Generation

If you need to generate textures manually (e.g., for pre-caching):

```typescript
import { TerrainTextureGenerator } from "@teskooano/celestials-terrestrial";

const textures = await TerrainTextureGenerator.generateTextures(planetObject, {
  resolution: TEXTURE_RESOLUTIONS.MEDIUM,
});

// Use textures with renderer
const renderer = new BaseTerrestrialRenderer(planetObject, {
  renderers: rendererMap,
  preGeneratedTextures: textures, // Skip generation, use these
});
```

## Troubleshooting

### WebGL Context Lost

If you see "THREE.WebGLRenderer: Context Lost" errors:

**Causes:**

- Too many WebGL contexts created simultaneously
- GPU memory exhaustion
- Browser tab backgrounded for extended period
- Driver issues

**Solutions:**

1. **Automatic Recovery**: The system automatically falls back to procedural material when context is lost
2. **Limit Concurrent Generations**: The system queues texture generation (max 3 concurrent) to prevent context loss
3. **Shared Renderer**: Uses a shared OffscreenRenderer instance to minimize context creation
4. **Manual Disable**: If context loss persists, disable texture generation:
   ```typescript
   createMesh(object, {
     ...options,
     useGeneratedTextures: false, // Use procedural shaders
   });
   ```

**Prevention:**

- Generate textures sequentially for multiple planets
- Use lower resolution: `TEXTURE_RESOLUTIONS.LOW`
- Skip expensive passes: `skipErosion: true`

### Textures Not Appearing

1. Check that `useGeneratedTextures` is `true` (default)
2. Verify the object has `surface` properties
3. Check browser console for texture generation errors
4. Ensure WebGL is available (required for offscreen rendering)
5. Check if context was lost (see above)

### Performance Issues

1. Reduce texture resolution: `TEXTURE_RESOLUTIONS.LOW` (1024x512)
2. Skip erosion: `skipErosion: true` (faster generation)
3. Skip craters: `skipCraters: true` (faster generation)
4. Disable texture generation: `useGeneratedTextures: false`

### Material Not Upgrading

The material upgrade happens automatically every 60 frames. If textures take longer than expected:

- Check texture generation promise: `renderer.getTextureGenerationPromise()`
- Manually upgrade: `await renderer.upgradeToTextureMaterialIfReady(object)`
- Check if generation failed due to context loss (check console)
